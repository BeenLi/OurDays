# Decision 0001 —— 红点语义：标记「任何有评论」的日程

- **日期**: 2026-07-03
- **状态**: Accepted（用户在澄清问题中选定「标记任何有评论的日程」）
- **范围**: req1

## 决策
日历事件块上的小红点表示该日程有 **≥1 条未删除评论**（`EventComment.deletedAt == nil`），无论评论作者是本方还是对方；**不**采用「未读」语义。

## 备选与理由
- **(选中) 任何有评论**：与用户字面诉求「有评论的日程」一致；实现最简（只查存在性，不碰 `isRead`）；不依赖未读状态机。代价：红点会长期常驻（含自己发的评论），可能略显噪声。
- (否决) 只标记未读：更符合「红点=待处理」的直觉、看过即消，但与用户明确选择相悖，且引入与「动态」tab 未读逻辑的耦合。

## 影响
- 红点数据源 = `EventCommentIndicatorPolicy.commentedAnchorKeys(comments)` 的存在性判断，不读 `isRead`。
- 不改 `ActivityFeedPolicy` / 未读角标逻辑。
- 若日后想要「未读」变体，可在同一 Plan 上加 `unreadAnchorKeys` 分支，不影响本决策落地。
