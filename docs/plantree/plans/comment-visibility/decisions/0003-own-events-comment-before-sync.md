# Decision 0003 — 我的日程以 mirrorKey 为线程键，不等同步也能先发起评论

- **日期**：2026-10-23　**状态**：Accepted，#24 已落地（随 1.6）
- **范围**：req2 的延伸；取代 [0002](0002-own-event-detail-resolves-persisted-mirror.md) 里"无孪生则不显示评论区"的门槛

## 背景（原本的工作方式）
0002 让我的日程详情按 `mirrorKey` 找到持久化孪生后才显示评论区，所以刚创建、还没同步过的自有事件没有评论区，只能等对方先评论。用户想在自己的日程上先开话题。

## 决策
1. 我的持久化镜像以 `mirrorKey` 命名（SwiftData id 与 CloudKit recordName 都是它），对方导入的副本也以同一条记录命名 ⇒ `mirrorKey` 在两台设备上就是线程键，创建事件那一刻就已知。显示镜像按 `mirrorKey` 锚定；有孪生时仍优先用孪生。
2. 详情页的评论可用性分三种：对方的事件和持久化镜像总有线程；我的显示镜像在有孪生、或事件落在共享窗口内（配对日起 + 已批准的历史申请）时有线程；对方看不到的自有事件显示一行说明，不给输入框。
3. 红点同样回退到 `mirrorKey`，我自己的评论立刻亮点。

## 影响
- 不变量：**不要给自有持久化镜像用 UUID id**。`mirrorKey` 里带 occurrence 时间，改期会开新线程（既有行为）。
- 冒烟 step 9b：owner 在未同步的自有事件上评论 → partner probe 看到 → partner 回复 → owner 看到两条。
- 0002 的「同步后可评论」占位提示不再需要。
