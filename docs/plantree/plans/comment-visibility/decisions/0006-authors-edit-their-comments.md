# Decision 0006 — 作者可以编辑自己的评论，编辑会传到对方那边

- **日期**：2026-11-25　**状态**：Accepted
- **范围**：`CommentEditPolicy`；`EventCommentsSection` 左滑编辑和输入框；`SyncCoordinator.foregroundSync` 评论导入和补传

## 背景（原本的工作方式）
`CommentService.edit` 和 CloudKit 记录上的 `editedAt` 字段早就有，但界面上没有入口。导入时 `upsert(comments:)` 直接用云端的 `body` / `editedAt` 覆盖本地，所以就算本地改了，只要上传没成功，下一次同步就会改回旧内容。

## 决策
- 只有作者能编辑自己的评论（和删除同一条规则，见 0005）。左滑出现"编辑"，内容放回输入框，确认后保存。
- 保存后马上把记录上传到评论所在的 zone（日程主人的 zone，和发评论同一条路由）。
- 导入时比较 `editedAt`：本地的比云端晚（超过 1 秒，CloudKit 日期只到毫秒）就保留本地内容，否则用云端的。另一台设备或对方的编辑照常导入。
- 补传：同步读回评论后，如果是我改的、云端那条还是旧的，就再上传一次，写回读到它的 zone。已删除的评论交给 0005 的补传。
- 气泡下方的时间后面显示"已编辑"。

## 备选与理由
- 用 alert 里的文本框编辑：多行评论放不下，和发评论的输入框体验不一致。
- 每次导入都保留本地 body：另一台设备（Mac）上的编辑会被旧内容挡住。

## 影响
- 不改 schema，`editedAt` 字段早已在 Production。旧版本收到编辑会显示新内容，只是没有"已编辑"标记。
