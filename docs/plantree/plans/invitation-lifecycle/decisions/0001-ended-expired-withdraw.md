# Decision 0001 — 「已结束」以结束时间为准；过期只针对待处理；撤销走创建者的 zone

- **日期**：2026-10-23　**状态**：Accepted，#21 已落地

## 背景（原本的工作方式）
邀请没有时间概念：事件早已过去，邀请仍可发起、仍挂在待处理里、仍计入角标；发出的邀请也没有收回的办法，只能等对方拒绝。

## 决策
1. **已结束 = 事件的结束时间已过**（全天事件到最后一天的下一个午夜）。进行中的事件仍可邀请。详情页隐藏邀请区、创建表单拒绝已结束草稿。
2. **过期只作用于待处理**：待处理且事件已结束 → 两端都显示「已过期」、进「已处理」、不可答复、不计角标。已接受/已拒绝/已取消是决定，永不过期。
3. **撤销**：发起方对待处理且未过期的邀请可撤销；本地置为已取消并标记待上传，写到创建者自己的 private zone；上传失败由既有的"创建待重传"自愈在下次同步补推；对方导入时终态压过待处理。
4. 判断"现在"的函数都接受注入的时间，测试必须传入（1970 年代的夹具否则全算过期）。

## 备选与理由
- (否决) 以开始时间算已结束：进行中的事件仍有邀请价值（"现在过来一起"）。
- (否决) 过期也应用到终态：决定本身才是记录，不应被时间改写。

## 影响
- 字符串新增撤销按钮、「已过期」、已结束的校验提示。
- 用户要求每个影响同步的功能都要有冒烟覆盖，不只单元测试 → step 11。
