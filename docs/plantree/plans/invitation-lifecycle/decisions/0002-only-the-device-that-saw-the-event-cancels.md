# Decision 0002 — 只有见过这条日程的设备，才能因为它不见了而取消邀请

- **日期**：2026-11-23　**状态**：Accepted　**PR**：#57
- **范围**：`InvitationLocalEventSyncPolicy`，同步里"已接受的邀请对应的日程被删了就取消"这一步

## 背景（原本的工作方式）
接受邀请时，App 会往本机的系统日历写一条共同日程，并把它的 eventIdentifier 存进邀请。之后每次同步都检查这条日程还在不在：先按 ID 找，找不到再按标题加时间匹配。都找不到，就把邀请改成「已取消」，相当于用户在系统日历里删掉了它。

问题是 eventIdentifier 只在本机有效，而日程只存在一台设备的日历里。同一 Apple ID 的另一台设备（iPad、以后的 Mac）可能还没收到 iCloud 日历的同步，也可能永远收不到（日历建在「我的 iPhone」本地），没有日历权限时则所有日程都找不到。这几种情况下，它都会把一个谁也没退出的邀请取消掉。

## 决策
1. 每台设备在本机记下"我在自己的日历里见过这条日程"的邀请 ID（`SettingsStore.invitationIDsWithLocalEventSeen`，只存在本机）。
2. 只有记录里有的邀请，日程不见了才取消。从没见过的就不处理，等 iCloud 日历同步过来之后再开始算。
3. 没有日历读取权限时，这一步什么都不判断。
4. 已经不是「已接受」的邀请，从记录里移除。

## 备选与理由
- 在邀请记录里写一个"是哪台设备建的"标记：要改 CloudKit schema，还要重新部署 Production。而且 iCloud 日历同步过来之后，另一台设备本来也应该能判断删除。所以不采用。
- 平台判断（Mac 上不取消）：iPad 的情况照样存在，问题没解决。

## 影响
- 老用户升级后，第一次同步会把现有的日程都记成"见过"，之后删除照常生效。
- 对方那台设备（邀请的创建者）也受益：它用标题加时间去找对方接受的日程，以前找不到就会取消，现在不会了。
