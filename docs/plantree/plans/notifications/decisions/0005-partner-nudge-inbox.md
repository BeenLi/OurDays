# Decision 0005 — 提醒信箱：邀请和邀请回应的可见推送

- **日期**：2026-11-26　**状态**：Accepted　**PR**：#84

## 背景（原本的工作方式）
[0004](0004-comment-alert-push.md) 让「对方评论我的日程」走可见推送，靠的是那条评论写在**我的** zone。邀请不一样：邀请写在**发起人**的 zone（`CloudKitInvitationWritePolicy`），受邀方只能经共享库看到，而共享库只有「任何记录变化都触发」的数据库订阅。所以新邀请仍然要等静默推送唤醒 App、同步完才发本地通知。

## 决策
- 新记录类型 `PartnerNudge`（`kind`、`text`），记录名 `nudge:<kind>:<邀请记录名>`。谁想让对方立刻知道，就在保存邀请成功后，往**对方的 zone**（经共享库）再写一条 nudge：
  - 我新建待处理的邀请 → `invitation`
  - 我接受 / 拒绝对方的邀请 → `invitation-accepted` / `invitation-declined`
  - 撤销、取消、已归档不发。
- 接收方私有库每种 kind 一条 `CKQuerySubscription`（只在新建时触发），标题分别是「<昵称> 邀请你 / 接受了你的邀请 / 拒绝了你的邀请」，正文取 `text`（邀请标题）。
- 记录名固定，用 `ifServerRecordUnchanged` 保存：重传时服务器拒绝已有记录，不会重复推送。写 nudge 失败一律忽略。
- 去重与 0004 相同：以「这条 nudge 的推送确实到过这台设备」为准（通知中心里还在的推送 + 前台看到或点开过的，记录名即 nudge 记录名），到过的那条邀请不再发本地通知。对方是旧版本（不写 nudge）、或推送没送到时，照旧发本地通知。
- nudge 保留 7 天后由接收方在启动时清掉；解除配对时随前任的评论、邀请一起删除。清理只用记录 ID 和系统创建时间，不读字段，所以没有改 `CloudKitForegroundQueryPolicy`，不会触发整库重拉。

## 备选与理由
- **共享库数据库订阅按 `EventInvitation` 类型过滤 + 通用文案**：新建、修改、删除都会触发，历史申请也借用这个类型传输，会重现 0002 之前的「幻影推送」。
- **把邀请改写到受邀方的 zone**：旧版本读不到，破坏兼容。
- **「邀请被回应」直接订阅我库里邀请记录的更新**：可行，但更新订阅在后续任何修改时还会再触发，不如统一走 nudge。
- **自建推送中转服务器**：见 0004。

## 影响
- Production 要部署 `PartnerNudge` 记录类型后才生效；没部署时写入失败、订阅保存失败，行为与之前相同。
- 只有发送方升级后才写 nudge。
- 接收方若在推送到达前就同步完，会同时看到本地通知和推送。
- 历史申请、日程主人在评论串里的回复还没有接入信箱，以后可以加新的 kind。
