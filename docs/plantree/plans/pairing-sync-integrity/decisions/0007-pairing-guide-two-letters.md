# Decision 0007 — 配对引导：把"两封信"画出来

- **日期**：2026-10-29　**状态**：Accepted
- **范围**：「我们」页配对卡片、发起配对的邀请页、接受邀请后的回发弹窗、日历页的引导卡片
- **设计稿**：5 张画板（配对原本怎么工作 & 卡点、邀请之前、进度卡、对方回发、打不开链接）

## 背景（原本的工作方式）
真实用户在配对里卡住。原因不在某个按钮，而在配对本身的形状：

- 没有服务器，每个人的日程只在自己的 iCloud zone 里。对方能看到我，是因为我把我 zone 的 CKShare 链接给了 TA。
- 所以 `PairingSettingsPolicy.status` 要两个条件同时成立才是「已配对」：我的分享里有对方（`outgoingShareParticipantIDs`），我也接受了对方的分享（`partnerShareOwnerID`）。配对是**两次链接交换**：我寄出 → TA 收下 → TA 回寄 → 我收下。
- 以前的界面只描述状态，不说下一步：
  - 对方收到的只有一串 icloud.com 链接，没说要先装 App、开 iCloud、别在微信里点（见 [0006](0006-invite-link-needs-icloud-for-app.md)）。
  - 发出链接后（等待对方接受）卡片上只剩 iCloud 图标，想再发一次要去「更多 › 共享人与邀请链接」。
  - 第 3 步「对方回寄」完全没有提示：收下的一方看到"下一步发起配对，邀请对方加入"，像是要去邀请别人；发起方只看到"等待对方共享"，不知道该让对方做什么。

## 决策
1. `PairingGuidePolicy` 把五种 `PairingStatus` 翻译成"我是发起方还是接收方 + 现在等第几步"。接收方是否已回寄，看 `sentInviteBackToOwnerID` 是否等于当前伴侣（换人或回到未配对时自然失效 / 被清空）。
2. 配对卡片在未配对的各状态下显示：第 N 步 · 共 4 步、一句话的下一步、四个点的进度线（点的颜色是该谁动手：青色是我、珊瑚色是 TA），以及每步唯一的主按钮：发起配对 / 再发一次 / 提醒 TA 回发（分享一段文字）/ 回发邀请给 TA。等对方点开时多一个「TA 打不开链接？」帮助页。
3. 「发起配对」先打开我们自己的邀请页，用 `ShareLink` 发出一段话：App Store 地址 + 三步说明 + `share.url`。苹果的 `UICloudSharingController` 保留在邀请页底部和「共享人与邀请链接」里，用来管理共享人。
4. 接收方收下对方的分享后（`waitingForYouToShare` 且未回寄），弹一次「你已收下 TA 的日历 · 最后一步：回寄你的信」；点「回发邀请」跳到「我们」页并直接打开回寄的邀请页。每位伴侣只弹一次（`shareBackPromptShownForOwnerID`）；带 `-ShareCalSeedProfileName` 的冒烟启动不弹。
5. 日历页的引导卡片新增 `.shareBack`，排在"选择要共享的日历"之前：回寄不需要日历权限，而在那之前对方看不到我的任何东西。

## 备选与理由
- 继续只用苹果的共享面板：它只发一个链接，正是对方不知道该做什么的源头；面板里的文字我们也改不了。
- 只改文案不加进度：状态名（等待对方共享 / 等待你共享）本身就容易看反，画出四步能让两边看到同一张图。

## 影响
- 用 `ShareLink` 发出后无法确认是否真的发送成功；回寄一方点「发送邀请」即视为已回寄，没发成功可以在卡片上「再发一次」。
- 新增两个 UserDefaults 键：`sentInviteBackToOwnerID`、`shareBackPromptShownForOwnerID`。
