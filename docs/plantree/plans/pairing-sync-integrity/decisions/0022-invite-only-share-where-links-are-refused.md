# Decision 0022 — 账户所在地区不让建链接分享时，改用仅受邀者分享

- **日期**：2026-11-26　**状态**：Accepted

## 背景（原本的工作方式）
「发起配对」只建一种分享：任何拿到链接的人都能加入（`publicPermission = .readWrite`），链接放进我们自己的邀请文案里发出去。Apple 的共享面板也只给这一种选项，原因见 CLAUDE.md：让用户把分享切成「仅受邀者」会让对方打不开，切回去还会把已加入的人移除。

2.0 的诊断信息（0020）拿到了一对中国大陆区 iCloud 账户的结果：建链接分享被服务器拒绝，`serverRejectedRequest`，底层 "ShareTypeUnsupported" (14000)，server message "Cannot perform action due to region"；同一账户在临时 zone 里建仅受邀者分享成功。也就是这类账户永远配不上对。

## 决策
1. 建新分享被以地区原因拒绝时（`CloudKitShareRegionPolicy.refusesLinkShares`），立刻改建仅受邀者分享（`publicPermission = .none`），不报错。
2. 仅受邀者分享没有能直接发的链接，所以不走我们的邀请文案，先弹一句说明（所在地区不支持链接邀请，请添加对方 Apple 账户的手机号或邮箱），再打开 Apple 的共享面板。这种分享的面板只给「仅受邀者」一个选项，链接分享的面板照旧只给链接一个选项，两边都不能互相切换。
3. 回寄时面板保存了带受邀者的分享，就记为「已回寄」。
4. 已有的仅受邀者分享在没人加入时，原有逻辑会尝试升级成链接分享；被地区拒绝就保留原样。
5. DEBUG 构建加启动参数 `-ShareCalForceInviteOnlyShare YES`，在普通账户上走这条路径，用来在模拟器上验证界面。

## 备选与理由
- 按语言或地区设置预先判断：账户所在区和设备地区不是一回事（这对用户设备界面是繁体），只有服务器的答复可靠。
- 所有用户都改成仅受邀者：对方必须用登记在 Apple 账户上的手机号或邮箱，微信里发链接这条最顺的路就没了。
- App 自己收手机号再调 `CKFetchShareParticipantsOperation`：要自己做查找失败、多账户、发送渠道的界面，Apple 的面板已经都有。

## 影响
- 能建链接分享的账户行为不变。
- 大陆区账户：多一步填对方手机号或邮箱；填的必须是对方 Apple 账户上的，否则对方打不开。接受方式不变（点开链接，或粘贴到「收到邀请链接」）。
- 配对后的同步、评论、邀请、解除配对都只看分享上已接受的参与者，和分享是哪一种无关。
- 被拒的那次请求每次「发起配对」会多花约一秒。
