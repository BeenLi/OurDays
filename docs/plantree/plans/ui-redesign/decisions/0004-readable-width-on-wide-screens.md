# Decision 0004 — 宽屏（iPhone Duo 展开）下列表内容限宽居中

- **日期**：2026-11-24　**状态**：Accepted　**PR**：（待开）
- **范围**：动态 / 邀请 / 我们 三个 tab 的列表布局

## 背景（原本的工作方式）
各 tab 的 List 直接铺满屏宽。iPhone 上没问题，但 iPhone Duo 展开横屏有 951pt 宽：「我们」的设置行约 600pt 宽，标签在最左、值（中文 / 去开启 / 版本号）在最右；配对卡正文排成一整行。另外「我们」用 inset-grouped List，页头和配对卡又各自加了 20/16pt 行内边距，导致标题比其他 tab 靠右、配对卡比下面的分组卡窄一圈；「动态」「邀请」的空状态贴在标题下方，日历的空状态卡却垂直居中；「邀请」没有待回复时没有副标题，标题比其他 tab 高一截。

## 决策
- 新增 `ourDaysReadableWidth()`（`ReadableContentWidthPolicy`，上限 640pt）：容器宽于 640pt 时，用 `safeAreaPadding(.horizontal)` 把两侧各加 `(宽 − 640) / 2`，List 本身仍铺满（从屏幕边缘滚动、纸色背景到边），内容居中。≤ 640pt（所有 iPhone、Duo 外屏、Duo 内屏竖屏）加 0，布局不变。用在动态、邀请、我们三个 tab。
- 「我们」页头和配对卡的左右行内边距改为 0，跟随 inset-grouped 的分组边距：标题与其他 tab 对齐，配对卡与下方分组卡左右边缘一致（iPhone 上两者都在 16pt）。
- 「动态」「邀请」的空状态改为 List 的 overlay，垂直居中，与日历一致。
- 「邀请」没有待回复时显示固定副标题「一起定下的安排 / Plans you make together」，四个 tab 的标题高度一致。

## 备选与理由
- (否决) `.frame(maxWidth: 640)` 包住 List：List 变窄后两侧留白不能滚动，滚动条也落在内容中间。
- (否决) `.contentMargins(.horizontal, …, for: .scrollContent)`：它设定的是滚动内容的边距本身，「我们」的 inset-grouped List 得再写死一个与系统分组边距相同的值才能保证 iPhone 不动；safe area 方式是在系统边距之外叠加，窄屏时为 0，不用碰系统边距。
- (否决) 日历 tab 也限宽：日视图的「我 / 对方」双泳道和周视图在宽屏上正需要宽度，留给后续宽屏布局再做。

## 影响
- iPhone 上可见的变化只有：「我们」标题和配对卡左移到 16pt、配对卡变宽到与分组卡同宽；动态 / 邀请空状态居中；邀请多一行副标题。
- Duo 内屏横屏里内容以 640pt 居中列显示，浮动 tab 栏不再贴着卡片。
